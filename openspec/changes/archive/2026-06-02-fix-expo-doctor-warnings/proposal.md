# Proposal: fix-expo-doctor-warnings

## Intent

`expo doctor` reports 3 failures (non-square icons, missing peer dep, 5 patch mismatches). These are all SDK 56 maintenance issues — no new behavior, no user-facing change. Fix them so the project passes all 21 health checks.

## Scope

### In Scope

- Resize+pad 3 icon files (`icon.png`, `android-icon-foreground.png`, `android-icon-monochrome.png`) to square 1024×1024 via ImageMagick
- Add `expo-asset` as explicit dependency in `package.json` via `npx expo install expo-asset`
- Bump 5 Expo packages to latest patch within SDK 56 via `npx expo install --check`
- Verify with `expo doctor` (all 21 pass) and `make validate` (format + lint + typecheck + test)

### Out of Scope

- Icon redesign or source asset creation — only resize/pad existing files
- Generating new icon sizes or formats (e.g., favicon, PWA icons)
- Any spec-level changes — no user-facing behavior is modified
- Refactoring or adding to the asset pipeline

## Capabilities

### New Capabilities

None — pure maintenance, no new features.

### Modified Capabilities

None — no spec-level behavior changes.

## Approach

Execute 3 orthogonal fixes in order, then verify:

1. **Icons** — Inspect source images, then `magick` resize long edge to 1024 + pad shorter edge with transparency to produce 1024×1024. Apply same transform to all 3 files.
2. **Missing dep** — `npx expo install expo-asset` (already in node_modules as transitive, just not declared).
3. **Patch bumps** — `npx expo install --check` and accept suggested upgrades.
4. **Verify** — `make validate` → `npx expo-doctor` → confirm 21/21.

## Risks

| Risk                                                                | Likelihood | Mitigation                                                          |
| ------------------------------------------------------------------- | ---------- | ------------------------------------------------------------------- |
| Icon subject extends to edge → padding creates noticeable letterbox | Low        | Inspect images first; if bad, adjust crop region                    |
| Patch bump regression in Expo core (56.0.4 → 56.0.8)                | Very Low   | Same SDK line; `make validate` will catch it                        |
| `expo install --check` interactive prompt hangs in non-TTY          | Low        | Use `npx expo install <pkg>@<version>` individual bumps as fallback |

## Rollback Plan

- Icons: 3 files are the only changes — restore from git (`git checkout -- assets/images/icon.png assets/images/android-icon-foreground.png assets/images/android-icon-monochrome.png`)
- `package.json` + `bun.lock`: `git checkout -- package.json bun.lock` then `bun install`

Both rollbacks are safe since no migration, schema, or config changes are involved.

## Success Criteria

- [ ] `npx expo-doctor` exits 0 with all 21 checks passing
- [ ] `make validate` passes (format, lint, typecheck, test)
- [ ] `icon.png`, `android-icon-foreground.png`, `android-icon-monochrome.png` are valid 1024×1024 PNGs

- [ ] All 5 bumped packages at latest patch within `~56.x` range
