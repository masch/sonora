# Build Tooling Specification

## Purpose

The build tooling MUST capture the R8/ProGuard mapping file generated during Android production builds and make it available as a named artifact for downstream pipeline jobs to consume.

This ensures the mapping file — which maps obfuscated class/method/field names back to their readable counterparts — is preserved from the ephemeral `android/` directory (generated by `npx expo prebuild`) into a known output location.

## Requirements

### Requirement: Mapping File Capture

The `eas-build-android-release-ci-unsigned` target in the Makefile MUST copy the R8/ProGuard mapping file from its Gradle output location to the artifacts output directory.

#### Scenario: Mapping file is copied after a successful build

- GIVEN a clean production build is initiated via `make eas-build-android-release-ci-unsigned`
- WHEN `:app:assembleRelease` and `:app:bundleRelease` complete successfully
- AND the APK and AAB have been moved to the output directory
- THEN the mapping file at `android/app/build/outputs/mapping/release/mapping.txt` MUST be copied to the output directory

#### Scenario: Mapping file does not exist (R8 not enabled, build failure, or file missing)

- GIVEN the mapping file is not present at the expected Gradle output path
- WHEN the target attempts the copy operation
- THEN the copy command MUST fail (exit non-zero)
- AND the target MUST abort so the pipeline surfaces the missing-mapping configuration issue (fail-fast contract)

### Requirement: Consistent Naming Convention

The mapping file MUST be given a predictable, configurable name in the output directory, following the same variable pattern used for APK and AAB outputs.

#### Scenario: Default mapping filename

- GIVEN no `OUTPUT_MAPPING` variable is explicitly set
- WHEN the Makefile target runs the copy command
- THEN the output file MUST be named `sonora-release-mapping.txt`

#### Scenario: Custom mapping filename via variable

- GIVEN `OUTPUT_MAPPING` is set with a custom filename
- WHEN the Makefile target runs the copy command
- THEN the mapping file MUST be copied using the value of `OUTPUT_MAPPING` as the output filename

### Requirement: Capture Position

The mapping file copy MUST occur after the APK and AAB are moved, ensuring all build artifacts are in their final locations.

#### Scenario: Order of operations

- GIVEN the target executes normally
- WHEN the build completes
- THEN the order of artifact moves MUST be: (1) APK move, (2) AAB move, (3) mapping file copy
